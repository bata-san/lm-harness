# プライバシーと脅威モデル

LLM Harness の目標は、**ハーネス (サーバ側) がプロンプト・モデル出力 (思考を含む)・ツール引数を永続化もログ出力もしないこと** です。
ただし、これは「どこにも平文が存在しない」という意味ではありません。推論を行うには平文が RAM 上に必ず存在します。
以下では、ハーネスが保証することと、保証できないことを分けて書きます。

## 1. ハーネスが保証すること

設定 `privacy_mode` (既定で `true`、管理画面「プロンプト/出力をログに残さない (推奨)」) が有効なとき:

- **ハーネス自身のログ** (標準エラー出力、管理画面のログ、インスタンスログ、監査ログ) に、プロンプト・出力・ツール引数・認証情報 (`Authorization` / `x-api-key` / Cookie) を書きません。
- **Anthropic 互換 API (`/v1/messages`) の上流エラー本文** は、クライアントへ返す文言として 200 文字までに切り詰めます。ログには HTTP ステータスと本文の長さだけを書きます。(OpenAI 互換の `/v1/*` は本文をそのまま中継するだけで、ハーネスはログに書きません。)
- **子プロセス (llama-server / vLLM / Strata / Ollama) の出力** から、プロンプトや出力のダンプらしい行を取り除きます。通常の状態行 (起動、ロード、性能統計など) は残ります。
- **ランタイムの起動フラグ** を次のように制御します。
  - vLLM: リクエストログを止める `--disable-log-requests` を付与します (利用者が `--enable-log-requests` を指定した場合は尊重します)。
  - llama.cpp: `--verbose` / `-v` / `--slot-save-path` を指定した起動は拒否します。
  - Strata: `--api-monitor` / `--slot-save-path` を指定した起動は拒否します。
- **ディスクへの保存**: プロセス出力は RAM 上のリングバッファ (1 プロセスあたり最大 4000 行) にだけ保持し、再起動で消えます。ハーネスは会話内容をファイルに書きません (チャット履歴の保存方式は後述の (c) を参照)。
- **プロセスの強化**: ハーネス本体は `PR_SET_DUMPABLE=0` とし、コアダンプを作りません。起動する子プロセスは `RLIMIT_CORE=0` で起動します (Linux のみ)。

`privacy_mode` を `false` にすると、上の制限のうち子プロセスの出力フィルタと起動フラグの制御が外れます。デバッグ用途に限り使ってください。

## 2. 脅威モデル

| 場面 / 攻撃者 | 平文の所在 | ハーネスの対策 | 残るリスク・推奨 |
|---|---|---|---|
| **(a) GPU ワークステーション (ローカル)** | 推論中の RAM (ハーネス・推論サーバのプロセス)、KV キャッシュ (VRAM)。`privacy_mode` では、ログ・ディスクには書かれない。 | ログ・ディスクへの書き出し抑止 (第 1 節)。ハーネスは非 dumpable、子は `RLIMIT_CORE=0`。 | **root は任意のプロセスのメモリを読めます。** 同一ユーザーの別プロセスも、推論サーバ (exec 後は dumpable に戻る) のメモリを読める可能性があります。**スワップ・休止状態 (hibernation) で RAM がディスクに永続化されることがあります。** 推奨: スワップを暗号化する (または無効にする)、休止状態を使うなら暗号化する。 |
| **(b) トンネル事業者 (Cloudflare / ngrok)** | トンネルの終端点で TLS が復号されるため、事業者はその時点の通信内容 (プロンプトと出力) を見られます。 | なし。ハーネス側の暗号化では、TLS 終端点で見える内容は防げません。 | 事業者を信頼しない場合は、Tailscale や WireGuard などで端末とワークステーションを直接結び、ハーネスを VPN 上のアドレスに bind してください。Cloudflare Access などのアクセス制御は、通信内容の秘匿には効きません。 |
| **(c) 保存されたチャット履歴 (vault)** | ブラウザ内で暗号化されるため、サーバにはパスフレーズも平文もありません。 | PBKDF2-SHA-256 (600,000 回) で鍵を導出し、非抽出の AES-GCM-256 で本文と見出しを暗号化します。サーバは `{id, updated_at, size, 暗号文}` だけを保持し、検索や解析はしません。 | サーバは UUID、更新日時、データサイズを見られます。ブラウザや端末が侵害されれば、暗号化前の内容は見えます。パスフレーズを忘れると、サーバ側には復旧手段がありません。 |
| **(d) 同一 LAN・第三者による通信の傍受** | 通信路上 (TLS 終端は前項のとおり) | ハーネスは既定で `127.0.0.1` に bind し、トンネルは認証設定後にのみ開始します。 | LAN へ公開する設定 (`0.0.0.0` など) では、TLS などの保護を別途用意してください。 |

## 3. 保護されないもの (明示的な非保証)

- **推論中の平文そのもの**: RAM と VRAM 上には、プロンプトと出力が推論中に必ず存在します。root、カーネルの脆弱性、コールドブート攻撃、デバッガによる読み出しは防げません。
- **ディスクへの書き込み全般**: `privacy_mode` が防ぐのは「ハーネスが書くこと」だけです。スワップ、ファイルシステムのジャーナル、クラッシュダンプ、systemd/journald へのログ転送 (ハーネスの標準エラー出力を取っている場合)、シェル履歴などは対象外です。
- **子プロセス出力フィルタの限界**: 行単位のヒューリスティックです。改行をまたぐダンプの後続行や、未知の書式は取りこぼす可能性があります。ランタイムのバージョンによってはログの書式が変わります。
- **ランタイム固有のログ**: vLLM と llama.cpp / Strata の抑止は、上のフラグが効く範囲に限られます。Ollama には、ハーネスが抑止するフラグがありません (ログ設定はランタイム側に依存します)。
- **ハーネスの外側**: ブラウザの表示内容、ブラウザの拡張機能、ブラウザ履歴、クライアント端末のクリップボードなどは、このリポジトリの対象外です。
- **メタデータ**: 接続時刻、送信元 IP、リクエストのサイズ、モデル名、トークン数の集計 (メトリクス) は記録されえます。これらは内容ではありませんが、利用パターンは分かります。
- **管理者の権限**: 管理者は設定を変更できます (`privacy_mode` を含む)。管理画面へのアクセスは、管理者パスワードと二段階認証の運用に依存します。

## 4. 推奨する運用

1. `privacy_mode` を有効にしたままにする (既定値)。
2. スワップを暗号化する、または無効にする。休止状態を使う場合も暗号化する。
3. 外部からアクセスする場合、事業者を信頼しないなら VPN (Tailscale / WireGuard) を使う。
4. 管理者パスワードと二段階認証 (TOTP) を設定する。
5. チャットの本文を守りたい場合は、vault のパスフレーズを強いものにし、忘れないよう管理する。
